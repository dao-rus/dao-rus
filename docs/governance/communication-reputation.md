# Два независимых измерения репутации ДАО Русь

Статус: согласованная концепция; автоматическое накопление реализовано в тестовой ветке за закрытым переключателем.
Дата: 2026-11-01.

## Назначение

**Базовая (человеческая) репутация** характеризует доверие к человеку: надёжность, исполнение обязательств и соблюдение договорённостей.

**Коммуникационная репутация** характеризует соблюдение норм общения: уважение границ, неагрессию, корректность взаимодействия в рамках Кодекса.

Это **разные независимые измерения**. Нелюдимый, немногословный или замкнутый участник может быть надёжным. Отсутствие общения или оценок не является отрицательной характеристикой. Непопулярность, несогласие с большинством, критика и манера выражаться сами по себе не должны считаться нарушением норм общения.

Коммуникационная репутация не влияет автоматически на базовую, на вес голоса, членство или право участия в вече. Обратное влияние также отсутствует.

## Единица учёта и область действия

- Репутация привязана к участникам Core (UUID), а не к Telegram ID.
- Коммуникационное отношение направленное: оценка А → Б независима от Б → А.
- Область коммуникационной репутации — вся ДАО Русь, а не отдельный Telegram-хаб.
- Вклад одного участника в коммуникационную репутацию другого ограничен диапазоном от −1 до +1. Он изменяется от новых событий 👍/👎 по правилу насыщения, описанному ниже.
- Самооценка запрещена. Повторная доставка того же Telegram-события не должна учитываться повторно. Разные новые реакции учитываются по правилам ниже.
- Отсутствие активности не меняет действующую оценку и не восстанавливает репутацию автоматически.

## Подсчёт и отображение

Внутренний баланс коммуникационной репутации участника: сумма текущих направленных вкладов других участников (−1, 0, +1). Он может быть отрицательным.

Публичное число: `max(0, внутренний баланс)`. При отсутствии входящих оценок вместо нуля отображается «Пока не оценён»; при наличии оценок и неположительном балансе — «0». Не раскрывать публично внутренний отрицательный баланс или авторов отрицательных оценок. Правила доступа к деталям и аудиту определяются отдельно.

Базовая репутация и её действующие правила подсчёта, отображения и истории не изменяются. Не объединять два числа в общий рейтинг.

## Автоматическое формирование из Telegram-реакций

Бот Хранитель получает **новые события** 👍/👎 под сообщениями участников хаба, устанавливает Telegram ID реагирующего и автора сообщения, сопоставляет обоих с участниками Core. Если связь не подтверждена, репутация не изменяется.

Для каждой направленной пары А → В хранится текущий вклад `r` в диапазоне −1…+1, исходно 0. Для каждого **нового** 👍: `r = min(1, r + 1)`; для каждого **нового** 👎: `r = max(-1, r - 1)`. После достижения границы дальнейшие реакции того же знака не изменяют вклад, но противоположная реакция сдвигает его на один шаг к нулю. Примеры: 👎, 👍, 👍 дают −1 → 0 → +1; 👍, 👍, 👎 дают +1 → +1 → 0. Порядок событий существенен.

Снятие реакции **не отменяет** ранее учтённого репутационного действия. Повторная доставка того же события не учитывается; для этого переходы записываются в журнал с уникальным Telegram `update_id`. Состояние реакции сообщения и Telegram update ID позволяют отсечь дубликаты, неизменившиеся состояния и устаревшие обновления одного сообщения. Новый переход после снятия предыдущей реакции учитывается.

`update_id` также задаёт порядок между разными сообщениями и хабами. Так как saturating `+1/-1` некоммутативен на границах, при позднем поступлении более раннего update вклад пары пересчитывается по журналу в порядке `update_id`; обычные последовательные updates применяются инкрементально. Одновременные транзакции пары сериализуются блокировкой пары.

Накопительный вклад сохраняется без временного затухания и не вычисляется повторно из текущего количества активных реакций под сообщениями. Ручный API оценки отключён ответом `410`; профиль доступен только для просмотра. Исторические реакции, существовавшие до включения механизма, **не начислять задним числом** без отдельного решения. Переменная `TELEGRAM_COMMUNICATION_REPUTATION_ENABLED` включает начисление только при точном значении `true`; по умолчанию начисление выключено.

Модерация Telegram-хаба остаётся самостоятельным механизмом: уникальные реагирующие и скользящее окно 24 часа по правилам конкретного хаба. Накопительную коммуникационную репутацию не использовать вместо модерационных порогов; санкции не превращать автоматически в репутационные оценки.

## Требования к реализации

1. Переиспользовать существующие связи Telegram identity ↔ Core participant, хранение Telegram-реакций и аудит; не создавать вторую базу участников.
2. Изменить существующую экспериментальную реализацию коммуникационной репутации: модель одной ручной оценки не соответствует накопительному насыщаемому вкладу. Выбрать минимальную надёжную схему для состояния пары и идемпотентных событий.
3. Обеспечить глобальный (межхабовый) вклад А → В от −1 до +1; новые события учитываются один раз, в правильном порядке, атомарно.
4. Сохранить аудит, корректную конкурентность, защиту от повторных и устаревших Telegram updates, отсутствие начисления при самооценке и неподтверждённой связи с Core.
5. Проверить последовательности 👍/👎 и насыщение, снятие реакции, повторную доставку, порядок событий, межхабовую уникальность, приватность, независимость базовой репутации и 24-часовой модерации.
6. Не включать автоматические санкции, Telegram webhook и production в рамках реализации этого документа.

## Отдельные вопросы для будущего решения

- Интерфейс коммуникационной репутации только для просмотра; ручные действия в текущей тестовой реализации должны быть отключены до выпуска.
- Правила доступа к истории и возможность апелляции к оценкам.
- Как поступать с оценками после выхода или исключения участника; это не следует решать неявно при миграции.
