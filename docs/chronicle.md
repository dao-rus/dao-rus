# Публичная летопись разработки

После каждого значимого законченного изменения можно подготовить короткую публичную новость. Если изменение чисто техническое и неинтересно участникам, отдельная новость не нужна.

Формат новости: заголовок и 2–3 коротких абзаца. Человеческим языком объясняйте, что появилось, зачем это нужно участникам и что изменилось для них. Не пересказывайте технический отчёт: файлы, миграции и тесты упоминайте только тогда, когда без этого нельзя объяснить результат.

Соразмеряйте тон с масштабом изменения: не раздувайте значение небольших улучшений. Не описывайте ещё не реализованные возможности как уже существующие.

Основой для новости служит итоговый отчёт Codex и, при необходимости, комментарий автора. Решение о публикации и окончательный текст остаются под ручным контролем человека.
