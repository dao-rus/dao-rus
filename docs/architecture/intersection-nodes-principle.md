# Принцип пересечений и самообразующихся узлов сети

**Статус:** архитектурный принцип и направление дальнейшей разработки; не означает, что все перечисленные механизмы уже реализованы.

## Принцип

Любой общий признак, объединяющий участников ДАО, является потенциальным узлом сети. Совпадающие значения профиля (город, интерес, профессия, занятие, потребность и другие признаки) должны быть кликабельными: переход по ним показывает участников с соответствующим пересечением, с учётом приватности.

**Узел возникает из совпадения, а не из административного решения.** Для появления объединения по интересу не нужны отдельная регистрация сообщества, председатель или процедура приёма. Участники сами формируют его, указывая соответствующий признак.

## Два уровня

1. **Пересечение:** динамическая выборка людей с общим признаком. Минимальный результат перехода по ссылке — список этих людей.
2. **Устойчивый узел:** для стабильных типов пересечений, прежде всего географических и тематических (город, интерес), доступна собственная доска объявлений, привязанная к тому же признаку.

Базовая схема: **признак → участники → доска объявлений**. Один участник может одновременно входить во множество пересекающихся узлов.

## Направление разработки

- Стремиться к **общему механизму** поиска пересечений и узлов вместо независимых реализаций для городов, интересов и других полей.
- Сохранять различие между динамической выборкой и устойчивым узлом с доской; не создавать доску автоматически для каждого произвольного слова.
- Постепенно нормализовать значения и синонимы: например, «IT», «Айти», «Информационные технологии». На первом этапе допустимы буквальные совпадения; правила семантического объединения требуют отдельного проектирования.
- Не раскрывать скрытые поля профиля и не позволять через выборки восстанавливать приватные сведения.
- Повторно использовать существующие механизмы географических сообществ, объявлений и фильтрации участников, а не дублировать их.
- По мере развития оценивать производительность индексов, нормализацию словаря, устранение дублей и качество сопоставления признаков.

## Ближайший практический ориентир

В профиле участника город и интересы должны вести к соответствующему пересечению. Для города — к географическому узлу и его доске, когда он определён; для интереса — к списку людей с тем же интересом и, по мере развития, к тематической доске. Отключённый общий каталог участников не должен автоматически уничтожать возможность навигации по допустимым пересечениям.

## Открытые вопросы оптимизации

- Какие типы признаков считать устойчивыми узлами и когда им создавать доску?
- Как объединять синонимы и различать омонимы, не навязывая людям административный словарь?
- Как обеспечивать устойчивые адреса узлов при переименовании и объединении понятий?
- Как согласовать видимость участников, поиск и публикацию объявлений?

Принцип определяет направление, но **не предписывает преждевременно вводить универсальную сложную модель данных**. Реализация должна развиваться поэтапно и сохранять простоту пользовательского опыта.
