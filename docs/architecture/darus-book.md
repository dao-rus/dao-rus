# Книга DARUS: чеканка и удержания

Существующая `darus_ledger` остаётся append-only журналом чеканки по версионным
`reward_rules`. Миграция 045 не меняет её ограничения, записи и правила.
`darus_book` — единая аудируемая проекция: `UNION ALL` прежней чеканки и новых
`darus_movements`. Баланс участника — сумма `amount` в этой проекции, без
изменяемого столбца баланса и без вычислений через JavaScript float.

`darus_holds` связывает положительную сумму с инициатором и предметным объектом
`(source_type, source_id, participant_id)`. AFTER INSERT создаёт один отрицательный
`hold` в движениях; если денег не хватает, откатывается и удержание, и движение.
`distribution` и `refund` — положительные движения из удержанного, не чеканка.
Остаток объекта — минус сумма его движений. Возврат возможен только владельцу
удержания. Удержания и движения не изменяются/не удаляются/не очищаются TRUNCATE.

БД сериализует списания по Participant и раздачи/возвраты по удержанию, проверяя
баланс и остаток при каждом INSERT, включая прямых SQL writers. Domain helpers
в `darus-holds.ts` выполняют каждую операцию в транзакции; раздача нескольким
людям атомарна. Денежные суммы — строки с максимум шестью десятичными знаками.

Повторные debit, distribution, refund используют стабильный ключ
`(source_type, source_id, participant_id)`. Тип источника должен различать
назначения (например, тариф, раздачу и возврат остатка); повтор возвращает
существующий ID, изменение суммы, вида операции или удержания — конфликт.
Одно удержание не может получить второй debit. Advisory claims domain helpers
нужны для успешного concurrent retry, ограничения и триггеры охраняют данные
независимо от этих helpers. Helpers используют READ COMMITTED.

У механизма нет публичного API, UI, Telegram-операций или переводов между
участниками. Domain service отвечает за право расхода и выбор адресатов.
Наличие primitive refund не разрешает возврат тарифа Вече: эта предметная
политика определяется Уставом, а книга обслуживает и другие будущие объекты.
`getDarusBookWithDatabase` отдаёт полную историю для аудита. Существующая страница
«История начислений» и reward-feedback остаются проекциями прежней чеканки;
новый UI движений в Q-005 не добавляется. Пока primitive не подключён к domain
действиям, новых production движений нет, все прежние балансы неизменны.

## Изолированная проверка

`DARUS_TEST_DATABASE_URL` принимается integration test только с host `127.0.0.1`
и БД `darus_tests`. Тест создаёт уникальную schema, применяет миграции, засеивает
синтетическое начисление до 045 и проверяет неизменность строк/балансов после неё.
Проверяются overdraw, concurrent spends/releases, idempotency, atomic batch,
возвраты и защита от прямого SQL изменения истории. Production данные и secrets
для этого теста не используются.
