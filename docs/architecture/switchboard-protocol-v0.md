# Коммутатор ДАО: протокол v0

- **Статус:** принято Ваном 15 ноября 2026 года как основа реализации (дополнено в тот же день: имя не требуется, «кто здесь» с порогом, независимость от Telegram в перспективе). Черновик протокола: устройство и правила решены, точные числа (пороги, веса, лимиты) подбираются при реализации.
- **Откуда:** концепция «ДАО Гиперхаб» (15 ноября 2026) и опыт аварии Beget: монолитное Ядро на одном сервере потеряло всё, автономный хаб на другом хостинге выжил.
- **Связанные документы:** [Intent и сборка пазла](intent-puzzle.md), [Принцип пересечений](intersection-nodes-principle.md), [Карма v0.1](reputation-v0.1.md) (частично пересматривается, см. п. 9).

## 1. Идея

Коммутатор — как телефонная станция: знает, кто есть и чего ищет, и соединяет людей с их согласия. Разговоров он не видит и не хранит. Всё личное живёт у человека — в его голове, его ИИ, его Telegram. Код коммутатора открыт и свободно распространяется: поднять свой может любой.

Цикл: **запись → поиск совпадения → просьба о соединении → согласие обоих → разговор напрямую → отзыв → доверие**.

## 2. Устройство

- **Участник** — человек, по желанию со своим ИИ (Claude, ChatGPT и т. п.).
- **Клиент** — через него участник говорит с коммутатором. Два вида: **бот в Telegram** (без установки, для всех) и **коннектор для ИИ** (MCP, на одну страницу кода: человек подключает его к своему ИИ один раз).
- **Коммутатор хаба** — хранит минимум (п. 3) и выполняет действия протокола (п. 6).
- **Другие коммутаторы** — тот же протокол у других хабов (ДАО Земля, тематические хабы). Каждый сам решает, доверять ли данным соседа.
- **Разговор** — после двойного согласия напрямую в Telegram, без коммутатора.

Первый коммутатор — хаб «Тени Руси» (PHP, HostiMan), первый клиент — бот `@Daorus_bot`. Ядро, когда вернётся, становится надстройкой (Вече, награды, профили) или отдельным хабом, а не центром.

## 3. Что хранит коммутатор и чего не хранит

Хранит:
- **людей:** Telegram ID, имя и @username из Telegram, короткое резюме, написанное самим человеком;
- **записи** (п. 5);
- **просьбы о соединении и согласия;**
- **соединения** (факт «эти двое связаны», дата);
- **отзывы и уровень доверия** (п. 9).

Не хранит: переписку, тексты разговоров с ИИ, личные данные сверх резюме, историю поиска.

## 4. Идентичность

- Ключ человека — **Telegram ID**: есть у всех, не меняется. Коммутатор фиксирует его сам при первом обращении; представляться не нужно.
- **Имя не требуется.** Коммутатору имя ни к чему: при соединении человек и так видит Telegram-профиль другого. По желанию — псевдоним «как меня называть в сети», видимый только после взаимного согласия, меняется свободно. Свобода не означает безответственности: доверие привязано к ID, а новый аккаунт начинает как новичок (п. 9).
- В будущем: ключи, которые создаёт сам клиент (пара ключей), — независимость от Telegram (п. 11).
- **ID не показывается до взаимного согласия.** Поиск возвращает записи без ID и имён — иначе список ID собирается поиском и используется для рассылок.
- При соединении бот присылает каждому ссылку на профиль другого по ID — работает и без @username. Если чат не открывается из-за настроек приватности, первое сообщение можно передать через бота.
- Коннектор ИИ доказывает, чей он, кодом: человек пишет боту `/key`, получает код для своего ID и вставляет его в коннектор. Код можно отозвать.

## 5. Записи

Два вида:

- **Интерес** — свободный текст о том, что человека занимает, плюс несколько слов-меток. Цели может не быть: «думаю о ДАО для жилищных кооперативов».
- **Намерение** — то, чего человек хочет добиться, с явными ключами: **вид** (нужно / есть / хочу сделать), **тема**, **город** (или «неважно»), **формат** (онлайн / вживую / неважно) и описание свободным текстом.

У каждой записи:
- **видимость:** «видно участникам коммутатора» или «только при совпадении» (в поиске не показывается; когда кто-то ищет похожее, хозяину приходит: «Кто-то ищет … Вот его строка о себе. Показать ему вас?»);
- **срок жизни:** запись гаснет, если её не обновлять, — коммутатор не зарастает мёртвыми записями.

Записи Обмена хаба («Мне нужно» / «У меня есть») становятся намерениями.

## 6. Действия протокола

1. **Записаться** — ID, резюме, согласие с тремя правилами Кодекса.
2. **Выложить или снять запись.**
3. **Найти** — по словам и меткам (интересы) или по ключам (намерения). Ответ — записи без ID и имён.
   **«Кто здесь»** — сводка без имён: сколько людей в сети, о чём чаще пишут, из каких городов. Показываются только группы от трёх человек (мельче — «несколько» или не показываются), считаются только записи, видимые всем: иначе по сводке можно вычислить конкретного человека.
4. **Попросить соединения** — только по найденной записи, не с произвольным человеком.
5. **Ответить на просьбу** — согласие или отказ; при согласии обоих — ссылки друг на друга (п. 4).
6. **Оставить отзыв** — после соединения (п. 9).

Формат обмена между клиентом и коммутатором и между коммутаторами — простой HTTP с JSON; точное описание полей пишется вместе с кодом.

## 7. Подбор

- Коммутатор сравнивает только явное: ключи намерений, слова и метки интересов. Это просто, прозрачно и проверяемо — как решено для «Ближе».
- Понимание смысла — на стороне ИИ участника: он превращает вопрос «не интересуется ли кто-нибудь вот этим?» в поисковые слова и отсеивает результаты.
- В центре нет алгоритма, который решает, кого кому показать.

## 8. Кто может войти

Любой, кто через бота согласился с тремя правилами Кодекса. Вступать в группу хаба не обязательно. Сеть растёт открыто, а доверие — из реальных взаимодействий (п. 9): полезное взаимодействие → доверие → сотрудничество → сообщество.

## 9. Доверие по Кодексу

- **Отзыв возможен только после настоящего соединения.** Через неделю бот спрашивает каждого: «Полезно» / «Нейтрально» / «Нарушил Кодекс» (какой пункт и пара слов, что случилось). Один отзыв на соединение с каждой стороны.
- **Отзыв — только о поведении в этом общении**, не о взглядах. Отзыв о взглядах недействителен: иначе доверие превращается в оценку убеждений и выдавливает несогласных (п. 2 Кодекса).
- **Вес отзыва зависит от доверия к тому, кто его дал.** Начальное доверие — у принявших Кодекс в хабах ДАО. Отзывы людей, общающихся только друг с другом, весят мало, из разных частей сети — много. Это защита от накрутки и сговора в открытой сети.
- **Старые отзывы постепенно весят меньше** — репутацию можно восстановить.
- **Уровни:** *новичок* (обычные лимиты) → *доверенный* (несколько «Полезно» от разных людей, нет свежих нарушений; отметка «можно доверять» в поиске, лимиты выше) → *под вопросом* (несколько независимых жалоб на нарушение Кодекса; **скрыт из поиска автоматически**) → *отключён* (не может пользоваться коммутатором; **только решением людей** — Вече или суда хаба).
- **Скрытых наказаний нет.** Человек видит отзывы о себе (пункт Кодекса и описание) и может ответить; отключение можно оспорить. Автор жалобы по умолчанию не раскрывается — чтобы отзыв не вёл к мести.
- **Пересмотр Кармы v0.1:** там репутация не влияет на полномочия, а оцениваемый не видит жалоб. В коммутаторе доверие влияет на доступ (скрытие, отключение), а содержание отзывов видно оцениваемому. Решение Вана от 15.11.2026.

## 10. Защита от злоупотреблений

- ID скрыт до согласия (п. 4).
- Просить соединения можно только по совпавшей записи; число просьб в день ограничено (больше у доверенных).
- Записи со сроком жизни (п. 5).
- Память об исключении и доверие **локальны** для коммутатора: общий «чёрный список» по всей сети стал бы центральным органом контроля. Соседний коммутатор может учитывать чужие отметки, но решает сам.

## 11. Устойчивость

- Коммутатор хранит мало — потерять его не страшно; участники с клиентом-ИИ держат копию своих записей у себя и могут отправить их заново.
- Коммутатор умеет полностью выгрузить свои данные; участник — свои.
- Копия данных хранится вне хостинга. Коммутатор поднимается на другом сервере без участия исходного.
- Живучесть сети — не в коде, а в числе экземпляров, в клиентах, знающих несколько коммутаторов, и в связи коммутаторов между собой: один экземпляр — сервер с адресом, его можно заблокировать.
- **Telegram — единая точка зависимости** (ID, бот, разговор). В протокол закладывается возможность ID, созданного клиентом, и разговора не только через Telegram; реализуется позже.

## 12. Мера успеха

Не число записавшихся и не число записей, а число соединений и доля отзывов «Полезно».

## 13. Открытые вопросы

- Пороги и веса доверия, лимиты просьб, срок жизни записей.
- Список тем для ключа «тема»: фиксированный, редактируемый или свободный.
- Точный формат HTTP JSON и описание коннектора MCP.
- Лицензия свободного распространения.
- Как связываются коммутаторы разных хабов и как обмениваются доверием.
- Чтение коннектором открытых документов ДАО (Кодекс, уставы, решения Вече) — «ИИ-ангел» у каждого в своём аккаунте.
- Перенос записей Обмена и участников хаба в формат протокола.
