# Intent и сборка пазла — рабочая гипотеза

- **Статус:** концептуальная заметка / точка возврата
- **Дата фиксации:** 2026-09-19
- **Связанный документ:** [Философия DAO Rus](../philosophy/philosophy-of-dao-rus.md)
- **Назначение:** сохранить найденный механизм, прежде чем переходить к проектированию реализации

## 1. Основной двигатель: «Я хочу / мне нужно»

Рабочая гипотеза: главным динамическим объектом DAO Rus является не членство,
публикация или голосование, а выраженная воля субъекта:

```text
Я хочу X
Мне нужно X
```

В философском слое это воля. В информационном слое ей соответствует компактный
объект `Intent`.

Важно различать содержание намерения и его технический идентификатор. `Intent`
может иметь ключ, ID, hash/signature и иное компактное машинное представление,
но один hash не содержит семантики, необходимой для поиска совместимых фрагментов.
Конкретная схема данных пока не определена.

## 2. Intent как первый фрагмент пазла

После публикации в разрешённом субъектом пространстве коммуникаций `Intent`
становится фрагментом пазла.

Система не обязана искать один готовый «ответ». Она может искать множество
комплементарных фрагментов:

```text
Intent
  +
Capability
  +
Resource
  +
другой Intent
  +
Relationship
  +
условия
  =
частичное или полное решение
```

Пример:

```text
«Нужно перевезти диван завтра из A в B»
+
«У меня есть пикап»
+
«Я завтра свободен»
+
«Могу помочь с погрузкой»
=
почти или полностью собранный пазл
```

## 3. Не бинарное совпадение, а степень достаточности

Композиция может удовлетворять намерение частично:

```text
35%
67%
92%
100%
```

Эти числа пока являются метафорой, а не спецификацией универсального рейтинга.

Принцип важнее конкретной математики: агент должен уметь различать:

- готовое решение;
- близкое решение;
- частичную конфигурацию;
- отсутствующий фрагмент.

Оценка достаточности предпочтительно принадлежит субъекту или его агенту, а не
центральному алгоритму, который объявляет единственную «правильную» меру
совпадения.

## 4. Дефицит становится поисковым объектом

Если пазл собран не полностью, важнейшим результатом matching становится не
просто «ничего не найдено», а описание **недостающего фрагмента**.

```text
Intent
→ внутренний matching
→ частичная сборка
→ обнаружение дефицита
→ поиск недостающего фрагмента
```

Именно дефицит может запускать распространение запроса за пределы существующей
сети.

## 5. Вирусность «на плечах потребности»

Если внутри сети нет нужного фрагмента, участник может знать человека вне DAO,
который им обладает.

```text
запрос
→ внутри сети решения нет
→ найден недостающий Capability / Resource
→ участник знает подходящего outsider
→ «Передать запрос»
→ обычное человеческое сообщение
→ outsider видит конкретную потребность
→ помогает решить её
→ возникает новая связь
```

Принцип:

**DAO приглашает человека не «в платформу», а в недостающую клетку конкретного
пазла.**

Поэтому приглашение несёт немедленную полезность и контекст. Человеку не нужно
сначала принять идентичность сообщества, зарегистрироваться ради регистрации и
только потом искать смысл участия.

Сначала возникает задача и полезное взаимодействие. Принадлежность и идентичность
могут возникнуть позже как результат повторяющейся кооперации.

## 6. Дефицит связности производит новую связность

Неудачный внутренний поиск не обязательно является ошибкой системы. Он может
быть механизмом роста.

```text
не хватает возможности X
→ сеть ищет X вовне
→ появляется человек / ресурс / компетенция X
→ текущий Intent решён
→ X остаётся доступным для будущих комбинаций
```

Таким образом, сеть потенциально растёт не случайным набором участников, а в
направлении реально обнаруживаемых дефицитов.

Каждый успешный внешний поиск одновременно:

1. помогает закрыть текущий Intent;
2. увеличивает пространство будущих решений.

Это кандидат на основной вирусный цикл DAO Rus.

## 7. Пользователь становится брокером связности

Цикл не заканчивается тем, что newcomer получил или оказал услугу.

Рабочая цепочка:

```text
OUTSIDER
→ INTRODUCTION
→ FAVOR / SERVICE
→ RECIPROCITY
→ RELATIONSHIP
→ BROKER
```

После положительного опыта человек может сам получить чужой запрос и передать его
следующему подходящему человеку.

Полный цикл:

```text
Intent
→ дефицит
→ внешний поиск
→ новый субъект
→ решение
→ новая связь
→ новый Intent
→ новый внешний поиск
```

Сеть воспроизводит себя через полезные отношения.

## 8. Сообщество как результат, а не условие

Предпочтительная последовательность:

```text
потребность
→ помощь
→ доверие
→ повторение
→ связь
→ сообщество
→ идентичность
```

а не:

```text
идентичность
→ членство
→ сообщество
→ активность
→ возможная польза
```

«Русь» в этой модели может пониматься как возникающая культура и структура
отношений, если взаимодействия систематически воспроизводят базовые принципы
DAO Rus.

## 9. Из множества Intent возникает общее

Тот же механизм масштабируется от частной задачи к общему делу.

Например:

```text
«Хочу детскую площадку во дворе»
+
37 близких Intent
=
потенциальный Common
```

Далее пазл может собираться из людей, компетенций, ресурсов, денег, разрешений и
готовности действовать.

Когда множество индивидуальных воль обнаруживает общий предмет, появляется
основание для совместной процедуры решения:

```text
Intent₁ + Intent₂ + ... + Intentₙ
→ Common
→ обсуждение / согласование
→ Veche / Decision
→ Agreement
→ Action
```

Отсюда рабочая гипотеза: **народовластие является одним из частных случаев
сборки комплементарных человеческих воль вокруг общего предмета**, а не отдельным
модулем голосований, пристроенным к системе сверху.

## 10. Кандидат на фундаментальный алгоритм DAO Rus

На текущем этапе главный алгоритмический объект проекта можно сформулировать так:

> Децентрализованная сборка комплементарных Intent, Capability, Resource и
> Relationship в конфигурации, достаточные для добровольно согласованного
> действия.

Короткая цепочка:

```text
Я хочу
→ Intent
→ Matching
→ Puzzle
→ Deficit
→ Search
→ Relationship
→ Agreement
→ Action
```

Если возникает общий предмет:

```text
множество Intent
→ Common
→ Veche
→ коллективное Agreement
→ Action
```

## 11. Что пока НЕ зафиксировано

Эта заметка намеренно не определяет:

- формат `Intent`;
- способ семантического matching;
- алгоритм вычисления степени достаточности;
- маршрутизацию запросов между узлами;
- модель приватности и раскрытия Intent;
- защиту от спама, Sybil-атак и злоупотреблений;
- устройство локальных AI-агентов;
- сетевой транспорт;
- экономическую модель;
- конкретную реализацию DAO Core.

Это следующие задачи проектирования. Их нельзя преждевременно принимать за
решённые только потому, что концептуальная модель выглядит связной.

## 12. Точка возврата

При возобновлении работы начать с вопроса:

**Что является минимальным `Intent` в протоколе и какая минимальная информация
необходима агенту, чтобы обнаружить комплементарность, не раскрывая лишнего?**

После этого отдельно проектировать:

```text
Intent schema
→ Matching
→ Sufficiency / Deficit
→ Routing
→ External handoff
→ Agreement
→ Action / verification
```
