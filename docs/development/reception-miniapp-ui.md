# Mini App Приёмной: анкета и запуск

Этап 2 [архитектурного решения](../architecture/reception-miniapp-onboarding.md).
API: [reception-applications-api.md](reception-applications-api.md).

## Реализованный интерфейс

`/reception/apply` — отдельная гостевая страница, не использующая Dev bot login,
Core-сессию или создание Participant. Telegram SDK загружается в браузере;
initData используется только в памяти и заголовке `Authorization: tma ...`.
При обычном открытии в браузере страница предлагает перейти к боту Приёмной.
Поля и предпросмотр доступны только после успешного GET собственной анкеты.
Ошибка загрузки блокирует запись, чтобы пустая форма не заменила сохранённые данные.

Город и род занятий обязательны, возраст необязателен. Согласие на публикацию
возраста по умолчанию выключено; очистка возраста снимает согласие. Предпросмотр
показывает возраст только при согласии. Персональный текст показывается как
экранированный plain text в полях и предпросмотре.
POST создаёт первую анкету, PUT исправляет сохранённую. Повторное открытие читает
сохранённые сведения. Во время запроса поля и повторная отправка блокируются.
Подтверждение: «Заявка сохранена. Ожидает отправки в Приёмную».
При 401 предлагается закрыть Mini App и открыть её заново через бота;
Core login вместо этого не предлагается. При неопределённом сетевом результате
UI разрешает безопасно повторить запись через идемпотентный API.

Редактируемые тексты находятся в `interfaceTextFields`, раздел «Приёмная».
Технические состояния загрузки, ошибки и сообщения авторизации отдельными
редактируемыми ключами не являются.

## Настройки Telegram и Core

- `APP_BASE_URL` — публичный HTTPS origin Core с доступной `/reception/apply`.
- `TELEGRAM_RECEPTION_BOT_TOKEN` — серверный токен именно бота Приёмной.
  Токен Dev bot для этой страницы не подходит.
- `TELEGRAM_RECEPTION_BOT_USERNAME` — username Приёмной для ссылки возврата в бот.
- `TELEGRAM_RECEPTION_MINI_APP_ENABLED=true` включает кнопку в обычном личном
  `/start`. По умолчанию false: до проверки кнопка не показывается.
- Существующие webhook secret, URL webhook и настройки форума/relay сохраняются.
  Кнопка добавляется к текущему приветствию; если приветствие выключено или
  пользователь уже в форуме, отправляется короткое предложение анкеты.
  Обычные текстовые сообщения продолжают идти через relay.

Кнопка — inline `web_app: { url: ... }`, а не обычная URL-кнопка и не ссылка на
Dev Mini App. Она предназначена для личного чата пользователя с ботом.
Telegram требует HTTPS URL для WebAppInfo; см.
[Mini Apps](https://core.telegram.org/bots/webapps#inline-button-mini-apps) и
[InlineKeyboardButton](https://core.telegram.org/bots/api#inlinekeyboardbutton).
Для этого способа запуска отдельный Main Mini App или menu button в BotFather
не требуется. При желании menu button можно позднее настроить на тот же URL;
это не замена проверке именно кнопки `/start`. Настройки Telegram автоматически
этим кодом не меняются.

## Порядок проверки перед включением для новичков

1. Развернуть проверенный commit и миграцию 052 в доступном по HTTPS тестовом
   окружении. Использовать отдельного тестового Reception bot и его токен;
   включить Mini App кнопку только для этого окружения. Production deploy
   выполняется по отдельному решению.
2. В личном чате этого бота вызвать `/start`, убедиться в наличии «Заполнить
   анкету», сохранении текстового приветствия и переписки. Открыть именно эту
   кнопку на Telegram Android и iOS; проверить корректный initData Reception bot.
3. На узком экране и с открытой клавиатурой заполнить город и занятия. Проверить
   чтение полей, прокрутку, отсутствие горизонтального переполнения, доступность
   согласия, предпросмотра и кнопки сохранения.
4. Указать возраст без согласия: он не должен появляться в предпросмотре.
   Включить согласие, затем очистить возраст: согласие должно сняться.
5. Отправить, проверить точное подтверждение сохранения. Закрыть и повторно
   открыть Mini App; исправить сведения, повторить отправку, убедиться в одной
   заявке и одной pending-операции публикации.
6. Держать окно открытым более 10 минут, попытаться сохранить: UI должен
   предложить открыть Mini App заново. Проверить отсутствие Dev login.
7. Проверить второго кандидата, существующего участника Core, отсутствие изменения
   профиля, работу обычного relay и отсутствие публикации/приглашения от анкеты.
   Старый auto-invite не меняется на этапе 2: его согласование с решением Хранителя
   обязательно до включения новой процедуры приглашений на этапе 4.
8. После проверки HTTPS и клиентских сценариев отдельно разрешить production
   deploy. Включить флаг кнопки после smoke на рабочем домене; учесть, что до этапа 3
   анкеты только сохраняются и сами в форум не отправляются.

Локальные тесты с синтетическим SDK и viewport 320/390 px не заменяют проверку
настоящих Telegram-клиентов, HTTPS, WebView-клавиатуры и актуальных настроек бота.
