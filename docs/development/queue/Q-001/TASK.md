# Q-001. Страница убытия

**Уровень риска:** обычное изменение. **Deploy:** да.

Страница `/admin/guardian/departures` (`apps/core/src/app/admin/guardian/departures/page.tsx`,
данные — `lib/guardian-departures.ts`).

## Сделать

1. **Период «с — по».** Два поля даты в форме GET-параметров. Без параметров — вся история.
   Счётчики «за 30 дней» и «всего» не трогать; добавить счётчик за выбранный период.
2. **Группировка по месяцам.** Заголовок месяца («Октябрь 2026») и записи под ним, новые сверху.
3. **Даты без времени.** `dateStyle: "long"`, часовой пояс Europe/Moscow, как у даты прихода.
4. **Счёт людей, а не событий.** Если у одного участника несколько событий ухода, в счётчиках
   он считается один раз; в списке события остаются все.
5. **Причина удаления** — показать, только если она уже хранится в данных. Если не хранится,
   ничего не добавлять и написать об этом в отчёте.

## Не делать

- Метку «удалён» не менять: решение по ней не принято.
- Новые тексты — через `interfaceTextFields`.

## Проверка

Typecheck, ближайшие тесты (`page.test.tsx`, `guardian-departures.test.ts`), тест на подсчёт
людей при двух событиях одного участника.
