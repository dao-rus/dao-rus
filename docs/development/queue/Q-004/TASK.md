# Q-004. Сверка «Приёмная ↔ Core»

**Уровень риска:** только отчёт. **Deploy:** нет. Код не менять.

Первый пункт backlog в разделе «Telegram / онбординг»: «Интегрировать „Приёмную ДАО Русь“ с
DAO Core…». Консультант не может по коду достоверно определить, что из него уже сделано.

## Сделать

По каждому подпункту указать **сделано / частично / не сделано**, со ссылкой на файлы и, где
можно, на проверку на production:

1. Разделение ролей ботов («Приёмная» и DAO RUS Dev bot / Хранитель).
2. Общий слой интеграции и связь `telegram_user_id ↔ core_user_id` без отдельных сущностей.
3. Проверка членства в форуме для пользователя Core.
4. Мягкое приглашение в форум тому, кто есть в Core, но не в форуме.
5. Фиксация шага онбординга и прекращение приглашений после вступления.
6. Обратный маршрут: участник форума без профиля Core → предложение зарегистрироваться.
7. Членство в форуме не обязательно для доступа к Core.

Также проверить на production подпункт третьего пункта backlog: реальные выходы из форума
приходят в webhook и пишутся в базу (`forum.left` / `forum.removed`) — число событий за
последние 30 дней.
