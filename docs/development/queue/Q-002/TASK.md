# Q-002. Сопоставление восстановленных из архива с экспортом Приёмной

**Уровень риска:** только отчёт. **Deploy:** нет. **Запись в базу:** запрещена.

Пункт backlog «Сопоставить людей, восстановленных из архива убытия, с экспортом Приёмной».
У восстановленных нет Telegram ID и события прихода, поэтому «В ДАО с» у них пусто.

## Сделать

1. Взять восстановленных из архива убытия (см. `docs/development/telegram-departure-archive.md`)
   и экспорт Приёмной из `apps/core/.local/`.
2. Сопоставить **только по нику**, только однозначные совпадения. Тёзок, смену ников и
   «похожие» ники не угадывать.
3. Разложить на три группы: однозначные, сомнительные, без совпадения.
4. Список с данными людей — в `apps/core/.local/queue/Q-002/matches.json` и удобный для
   чтения `matches.html` (группы, по каждому человеку: ник, найденная дата прихода, источник).
5. Если удобнее, написать скрипт dry-run; закоммитить его можно (без данных), но он не
   должен уметь писать в базу без отдельного флага `--apply`, и `--apply` не запускать.

## Отчёт

Числа по трём группам, путь к файлам, как запускался скрипт. Решение о записи в базу
принимает Ван.

Если экспорт Приёмной на этом ПК не найден — `STATUS: STOPPED` с описанием, что искали и где.
