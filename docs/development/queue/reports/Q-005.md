# Q-005 — списания, удержания, раздача и возврат DARUS

## Сделано

Additive migration 045_darus_holds.sql добавляет darus_holds, darus_movements, ограничения/индексы, защитные триггеры и единый view darus_book. Прежняя darus_ledger остаётся неизменяемой книгой чеканки по reward_rules: её строки, ограничения и правила не переписаны.

Удержание с назначением source_type/source_id создаёт один отрицательный debit; распределение/возврат — положительные движения из удержанного, без reward_rule и без чеканки. Возврат разрешён только владельцу удержания. Общий баланс теперь SUM(amount) по darus_book. Остаток удержания — минус сумма его движений.

Проверки достаточности денег и остатка выполняются PostgreSQL-триггером, включая прямые SQL writers. Списания сериализуются на Participant, раздачи/возвраты — на удержании. История append-only; UPDATE/DELETE/TRUNCATE новых таблиц запрещены. Domain helpers используют транзакции; многополучательная раздача атомарна. Ключ операции — (source_type,source_id,participant_id); identical retry возвращает прежний ID, изменение суммы/вида/объекта отклоняется. UUID нормализуются до advisory claim; строки суммы максимум с шестью знаками, без float.

Файлы: migration 045, darus-holds.ts, darus-holds.integration.test.ts, tokenization.ts, docs/architecture/darus-book.md. Полная история доступна через getDarusBookWithDatabase; существующая UI история начислений остаётся reward-проекцией. UI/API/переводы между участниками не добавлялись. Primitive refund не меняет предметное правило невозвратности тарифа Вече.

Отдельного backlog пункта для этого primitive в planned-actions.md нет; несогласованный пункт «Переводы DARUS» не отмечался как выполненный.
