# Q-011. Вече: нижняя граница подписей и фиксация правил

**Уровень риска:** обычное изменение с миграцией. **Deploy:** да, если миграция только
добавляет. Зависит от Q-007.

[Устав](../../../governance/charters/veche.md), п. 4.2.

## Сделать

1. Настройка в `/admin/veche`: **минимум подписей** (целое ≥ 1), отдельно для соты и для всего
   ДАО. Значение по умолчанию — 5 для обоих кругов (рабочая настройка пилота).
2. Порог = большее из двух: минимум подписей или `ceil(доля × население круга)`. Подпись
   инициатора, как и сейчас, не учитывается.
3. **Фиксация правил при созыве.** При создании сбора за вопросом сохраняются действующие
   значения: доля, минимум, итоговый порог, срок сбора, круг. Сбор и последующее вече считаются
   по сохранённым значениям; изменение настроек влияет только на новые сборы. Уже идущие
   сборы получают снимок по текущим настройкам при миграции.
4. На странице вопроса показывать порог и срок из снимка.

## Не делать

Не задавать долю подписей и паузу в production: их задаёт Ван.

## Проверка

Тесты: порог = максимум из двух при малом и большом круге; изменение настроек не меняет идущий
сбор; снимок для существующих сборов после миграции. Typecheck, миграция на реальной PostgreSQL.
