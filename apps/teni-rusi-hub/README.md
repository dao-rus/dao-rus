# Автономный хаб «Тени Руси» (PHP / MySQL)

Снимок исходников из установочных ZIP-архивов, подготовленных 7 ноября 2026 года при аварии прежнего VPS Beget. Сохраняется для восстановимости и дальнейшей разработки. Это НЕ выгрузка с актуального production; текущее состояние HostiMan не сверялось с этими файлами. Скрипт одноразовой передачи webhook также сохранён для истории, запускать его повторно без отдельного решения нельзя.

## Область миграции

Перенесён только сценарий вступления в Telegram-группу «Тени Руси» через существующего бота «Приёмная ДАО Русь» (@Daorus_bot):
- событие chat_join_request — запись заявки и отправка Кодекса с кнопками;
- callback_query — согласие/отказ и попытка approveChatJoinRequest/declineChatJoinRequest;
- /start hub — повторное предложение только для уже имеющейся заявки;
- worker.php — истечение срока и повторные попытки;
- отдельный реестр согласий MySQL и скрипт экспорта.

Это НЕ перенос всего Хранителя или Приёмной. Старые функции Core (личный relay, уведомления, OIDC-авторизация, Mini App «Мне нужно», административный интерфейс и другое) автономный PHP-хаб не обслуживает. Telegram допускает только один активный webhook для одного бота. При восстановлении DAO Core требуется продуманная маршрутизация или переключение. Согласие на правила хаба НЕ является вступлением в ДАО или верификацией.

## Где расположен снимок

- site/index.html и site/webhook.php: публичная часть, только их размещать под document root.
- private/src: PHP-обработчик, Telegram-клиент и доступ к базе.
- private/schema.sql: четыре таблицы trh_* в отдельной базе MySQL.
- private/config.example.php: безопасный шаблон; реальный config.php никогда не коммитить.
- private/bin/check.php: проверка PHP, MySQL и, опционально, Telegram.
- private/bin/worker.php: CLI worker, рекомендуется cron раз в минуту.
- private/bin/export-consents.php: экспорт согласий, содержащий персональные данные.
- private/bin/telegram-setup.php: исторический одноразовый скрипт переключения webhook; НЕ выполнять без нового плана.

Нужны PHP 8.2+, CLI, расширения pdo_mysql, curl, json, openssl, MySQL/MariaDB с InnoDB, HTTPS и права бота can_invite_users.

## Порядок восстановления без смены webhook

1. Содержимое папки site размещается в корне HTTPS-сайта. Остальные файлы — в соседнем закрытом каталоге teni-rusi-hub-private (не внутри www). Относительный путь Bootstrap.php в webhook.php рассчитывает на эту структуру.
2. Создать отдельную БД и импортировать private/schema.sql ОДИН раз в пустую базу. Не перезаписывать существующую базу с согласиями.
3. Создать защищённый private/config.php на основании config.example.php, заполнить реальными секретами локально и убедиться, что никакой PHP-файл с секретами недоступен по HTTP.
4. Запустить проверку из CLI: /usr/bin/php82 -f /var/www/s251544/data/teni-rusi-hub-private/bin/check.php. Проверка Telegram: та же команда с суффиксом -- --telegram.
5. Прежде чем подключать существующего бота, проверить webhook владельца, статус очереди Telegram и другие функции Приёмной. НЕ выполнять setWebhook или drop_pending_updates вслепую.
6. Только после контролируемой передачи обслуживания настроить CLI cron для worker.php и проверить реальный путь заявки, callback_query и допуска.

Фактический config.php, SQL-дампы, API-токены, OIDC client secrets, пароли, журналы запросов с персональными данными НЕ коммитить. При возможном возврате в Core использовать export-consents.php только через защищённый канал.

## Проверки снимка

Два источника: teni-rusi-site.zip и teni-rusi-private.zip. Для всех 11 исходных файлов SHA-1 Git blob в GitHub сверяется с локальным содержимым архивов; совпадение подтверждает дословную фиксацию. Синтаксис всех девяти PHP-файлов архивов локально проверен на PHP 8.4. Не проводились новые интеграционные испытания MySQL или Telegram и проверка действующего сервера.
