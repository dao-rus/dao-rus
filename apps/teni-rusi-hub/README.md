# Автономный хаб «Тени Руси» (PHP / MySQL)

Снимок исходников из установочных ZIP-архивов, подготовленных 7 ноября 2026 года при аварии прежнего VPS Beget. Сохраняется для восстановимости и дальнейшей разработки. Hub.php с 11 ноября совпадает с развёрнутым на HostiMan (см. «Состояние на 11 ноября»); остальные файлы — снимок установочных архивов, их соответствие серверу не сверялось. Скрипт одноразовой передачи webhook также сохранён для истории, запускать его повторно без отдельного решения нельзя.

## Область миграции

Перенесён только сценарий вступления в Telegram-группу «Тени Руси» через существующего бота «Приёмная ДАО Русь» (@Daorus_bot):
- событие chat_join_request — запись заявки и отправка Кодекса с кнопками;
- callback_query — согласие/отказ и попытка approveChatJoinRequest/declineChatJoinRequest;
- /start hub — повторное предложение только для уже имеющейся заявки;
- worker.php — истечение срока и повторные попытки;
- отдельный реестр согласий MySQL и скрипт экспорта.

Это НЕ перенос всего Хранителя или Приёмной. Старые функции Core (личный relay, уведомления, OIDC-авторизация, Mini App «Мне нужно», административный интерфейс и другое) автономный PHP-хаб не обслуживает. Telegram допускает только один активный webhook для одного бота. При восстановлении DAO Core требуется продуманная маршрутизация или переключение. Согласие на правила хаба НЕ является вступлением в ДАО или верификацией.

## Где расположен снимок

- site/index.html и site/webhook.php: публичная часть, только их размещать под document root.
- private/src: PHP-обработчик, Telegram-клиент и доступ к базе.
- private/schema.sql: четыре таблицы trh_* в отдельной базе MySQL.
- private/config.example.php: безопасный шаблон; реальный config.php никогда не коммитить.
- private/bin/check.php: проверка PHP, MySQL и, опционально, Telegram.
- private/bin/worker.php: CLI worker, рекомендуется cron раз в минуту.
- private/bin/export-consents.php: экспорт согласий, содержащий персональные данные.
- private/bin/telegram-setup.php: исторический одноразовый скрипт переключения webhook; НЕ выполнять без нового плана.
- private/bin/pull-updates.php (+ private/src/Drain.php): управление доставкой обновлений Telegram.
  - `--check` только читает: режим (webhook или опрос), очередь, время последнего успешного опроса, сводку заявок за 7 дней.
  - `--drain` разово: снимает webhook без сброса очереди, забирает накопленное через getUpdates, обрабатывает тем же Hub::receive и возвращает тот же webhook (до трёх попыток, с проверкой).
  - `--use-polling` переводит бота с webhook на опрос; очередь сохраняется. `--poll` — один прогон опроса для cron раз в минуту под flock (≈50 с, long polling): входящие соединения от Telegram не нужны, поэтому таймауты доставки на webhook перестают мешать. Пока webhook активен, `--poll` ничего не делает (Telegram отвечает 409). Обновление, которое не удалось обработать в трёх прогонах подряд, пропускается с записью в журнал ошибок cron, чтобы не блокировать очередь. В режиме опроса `check.php --telegram` показывает `webhook_set:false` — это ожидаемо.
  - `--restore` возвращает webhook, если он пуст (после прерванного `--drain` или для отказа от опроса); чужой webhook не заменяет.
  - Обработка идемпотентна: повторно доставленное обновление безвредно.
- private/bin/set-operator.php `<telegram_user_id>`: задаёт в config.php `operator_chat_id` — кому пересылать прочие личные сообщения боту. Без него такие сообщения по-прежнему игнорируются. Этот человек должен хотя бы раз нажать Start у бота.

Напоминания: если заявитель получил правила и не ответил, worker присылает правила заново с заголовком «Напоминание: ваша заявка в хаб ждёт ответа. Если хотите подумать — не спешите.» и теми же кнопками — в первые сутки после заявки каждые 4 часа, до 30-го дня каждые 12 часов (на практике в 9:00 и 21:00 МСК), дальше раз в неделю (Hub::REMIND_*). Напоминания идут, пока человек не ответит, бот не получит отказ 403 (напоминания прекращаются, `/start` присылает правила снова) или не истечёт срок заявки. Важно: после 5-минутного окна заявки Telegram не даёт боту писать человеку, который сам не запускал бота, поэтому напоминания доходят только до тех, кто хоть раз писал боту; остальным первое напоминание даёт 403 (`remind_403`). Первое сообщение с кнопками при этом остаётся у человека в чате с ботом и работает, пока заявка открыта. Ночью, с 23:00 до 9:00 МСК, напоминания не отправляются. Тем, кому правила не удалось доставить (`awaiting_start`), бот написать не может, и напоминаний нет. Время последнего сообщения хранится в `offer_due_at`; схема базы не менялась.

Срок ответа задаётся `response_seconds`: 0 — без срока (заявка открыта, пока человек не ответит; в базе `expires_at` = Hub::NO_EXPIRY, 01.01.2100), иначе от 60 секунд до 30 дней. Меняется скриптом `bin/set-response-days.php <дни 1..30 | forever> [--extend-pending]`; с `--extend-pending` продлеваются и заявки, ещё ждущие ответа (срок только увеличивается). В сообщениях заявителю срок не указывается. Удаляет ли сам Telegram давние заявки на вступление, не проверено; если заявки там уже нет, одобрение не пройдёт и заявка уйдёт в needs_review — человек может подать новую.

Личные сообщения боту, кроме `/start`, пересылаются оператору одним сообщением: текст — со строкой «Сообщение боту от: имя (@username)» сверху; фото, видео, документ, аудио, GIF и голосовое — копией с этой строкой в подписи; прочее (стикеры, кружки, слишком длинный текст) — строкой и пересылкой, двумя частями. Отправитель получает «Ваше сообщение передано организаторам хаба.». Если пересылка не удалась, обновление повторяется (webhook: ответ 500; опрос: следующий прогон). Если у отправителя открыта заявка, бот заодно присылает правила заново со свежими кнопками: раз человек написал сам, Telegram позволяет боту ему писать, и напоминания тоже возобновляются.

Ответы оператора: нажать в Telegram «Ответить» на сообщении, которое переслал бот, и написать ответ (можно фото, голосовое и т. п.). Бот копирует ответ отправителю от своего имени и отвечает оператору «Доставлено.» или причиной, почему нет. Сообщение оператора без «Ответить» никуда не уходит: бот подсказывает, как ответить. Какие сообщения у оператора к кому относятся, хранится в таблице trh_relays (migrations/2026-11-15-relays.sql).

## Минимум функций Ядра на время его недоступности (private/src/Community.php)

Пока DAO Core не восстановлен, хаб выполняет три его функции. Данные привязаны к Telegram ID, чтобы их можно было перенести в Ядро.

- **Память об исключении.** Бан в группе хаба (Telegram присылает `chat_member` со статусом `kicked`; бот — администратор, опрос запрашивает `chat_member`) записывается в `trh_exclusions`; оператору приходит уведомление. Снятие бана отметку не убирает. Повторная заявка того же аккаунта: оператору — «Заявка от ранее исключённого…», заявителю — правила с пометкой «Ранее вы были исключены из хаба…». После «Принимаю» согласие сохраняется, заявка ждёт решения (`needs_review` / `excluded_review`), оператору приходят кнопки «Допустить» / «Отклонить». Допущенный снова считается участником; отметка остаётся как история. Баны до выкладки этой версии хаб не видел.
- **Список участников.** Оператор пишет боту `/members`: все, кто принял правила (имя, @username, дата согласия, в группе ли сейчас — по getChatMember), отметки об исключении, а также исключённые, не принимавшие правила. Имена хранятся в `trh_people` (обновляются при каждом обращении человека к боту; недостающие берутся из Telegram).
- **Приветствие после «Принимаю».** Один раз, сразу после записи согласия (`Network::greeting`, вызов из `Hub::callback`): что хаб — ещё и сеть, что сеть пока мала, что хранится (Telegram ID, имя, @username, записи, дата согласия), что «Нужно» и «Есть» публикуются в группе с именем, а остальное видно без имени, и приглашение к первой записи. Тем, кто уже вошёл раньше, оно не отправлялось; не отправляется и ранее исключённым, пока оператор их не допустил. Любое обещание в тексте должно совпадать с кодом `Network.php`.
- **Репутация, шаг 1 (`Reputation.php`, таблицы `trh_group_messages`, `trh_reactions`, миграция `2026-11-16-reputation.sql`).** Бот запоминает номер и автора каждого сообщения группы (без текста, бессрочно) и реакции под ними: список положительных и отрицательных эмодзи — в `Reputation::LIKE` / `DISLIKE`, остальные не считаются. Свои реакции не засчитываются; анонимные реакции и сообщения (от имени группы или канала) записываются на оператора. Кто отреагировал, хранится для учёта «одна реакция на человека и сообщение» и никому не показывается; человек видит только свой счёт по кнопке «Репутация». Сбой хранилища не задерживает очередь опроса: он считается в отчёте как `reputation_error` и пишется в журнал ошибок. Решения о доступе счёт не принимает. **Порядок выкладки: сначала миграция, потом файлы.** Реакции на сообщения, написанные до выкладки, не считаются (бот их автора не знает).
- **Репутация, шаг 2 (миграция `2026-11-16-reputation-alerts.sql`, таблица `trh_rep_alerts`).** Сигнал: если за 30 дней дизлайки под сообщениями человека поставили не менее трети активных людей (активный — тот, кто за эти 30 дней написал в группе или поставил реакцию; считается по данным счётчика, поэтому в первые недели решает нижняя граница — не меньше 3 разных людей), оператору приходит сообщение «Сигнал по репутации», а самому человеку — уведомление, что организаторы посмотрят. Раз в 30 дней на человека; недоставленный оператору сигнал повторяется на следующем проходе; сигнал об операторе самому себе не шлётся; ночью (23–9 МСК) не отправляется. Сигнал — повод разобраться, не решение: исключение решается голосованием людей (см. следующий пункт). Кнопка «Рейтинг» (`/top`): публичный топ-10 по числу лайков, с именем и @username, без исключённых и отключённых. **Порядок выкладки: сначала миграция, потом файлы.**
- **Голосование об исключении (`Vote.php`, таблицы `trh_votes`, `trh_vote_rolls`, `trh_vote_ballots`, `trh_voters`, миграция `2026-11-16-vote.sql`).** Оператор пишет боту в личку `/vote @username` (или числовой id), бот показывает черновик с кнопками «Открыть» / «Отмена», после «Открыть» в группе появляется сообщение с кнопками «За исключение» / «Против». Голосуют принявшие правила (без отметки об исключении) и те, кого оператор подтвердил командой `/voter @username`; список фиксируется при открытии, сам человек не голосует; голос оператора равен остальным. Голос тайный и окончательный: в `trh_vote_ballots` только факт «проголосовал» (ни выбора, ни времени), выбор есть лишь в двух итогах голосования. Срок 3 суток. Голосование действительно, если проголосовала треть списка и не менее 5 человек; исключение принято, если «за» не меньше двух третей проголосовавших. Итог бот пишет в группу и оператору, исключает человека сам оператор. Имена людей для голосования бот берёт из тех, кого видел: писавшие в группу, поставившие реакцию, обращавшиеся к боту. Итог закрывается на проходе cron (ночью, 23–9 МСК, чуть позже срока). **Порядок выкладки: сначала миграция, потом `Bootstrap.php` вместе с остальными файлами.**
- **Журнал реакций.** Опрос запрашивает `message_reaction` и `message_reaction_count` (бот — администратор группы). Проба 16 ноября 2026 показала, что Telegram называет автора реакции обычного участника, а реакции анонимного администратора приходят «от имени группы». В отчёте опроса (`pull-updates.php --poll`) идут счётчики по меткам результата (`message_reaction:reaction_like`, `reaction_dislike`, `reaction_removed`, `reaction_own`, `reaction_unknown_message`, `message_reaction_count:reaction_count_only`, `reputation_error`); cron выбрасывает стандартный вывод, поэтому строки с `message_reaction` дописываются ещё и в `reaction-probe.log` в каталоге private (дата и счётчики, без имён и ID). Реакции, поставленные до включения приёма, бот не видит.
- **Обмен** вошёл в коммутатор (см. ниже): записи «Мне нужно» / «У меня есть» участников группы по-прежнему публикуются в группе.

Таблицы: migrations/2026-11-15-community.sql (trh_people, trh_exclusions, trh_signals, trh_dialogs); check.php проверяет все 9 таблиц.

## Коммутатор, шаг 1 (private/src/Network.php)

Реализация протокола `docs/architecture/switchboard-protocol-v0.md`; клиент — бот.

- **Вход в сеть без группы.** `/start` у того, кто не в сети, — приглашение с тремя правилами Кодекса и кнопкой «Принимаю» (`trh_net`). Участники группы хаба уже в сети. Имя не спрашивается: ключ — Telegram ID.
- **Меню всегда внизу экрана** (постоянная клавиатура): «Мне нужно», «У меня есть», «Хочу сделать», «Интерес», «Найти людей», «Кто здесь», «Обмен», «Мои записи», «О себе». Набирать команды не нужно; работают и `/find`, `/who`, `/me`, `/menu`, а `/start` — с любым хвостом (`?start=net` в ссылке).
- **Сразу после «Принимаю»** — один вопрос «Что вас сейчас занимает?»: ответ сохраняется как интерес и сразу показываются похожие записи. Нажатие любой кнопки снимает вопрос.
- **Записи** (`trh_signals`, до 500 символов, не больше 10 активных): видимость «видна в поиске» или «только при совпадении», город по желанию. Срок жизни: «Интерес» — без срока, «Хочу сделать» — полгода, «Нужно» / «Есть» — 90 дней; за неделю до конца бот один раз спрашивает «Продлить / Снять» (`warned_at`).
- **Совпадения сами приходят.** После сохранения записи автор сразу видит похожие открытые записи (общих основ слов не меньше двух). Хозяевам похожих записей (и открытых, и скрытых) бот пишет «Появилась запись, похожая на вашу» с кнопкой «Познакомиться» — не больше 2 в день, не ночью (23–9 МСК), отключается кнопкой «Не присылать совпадения» или в «О себе» (`trh_net.notify`). «Мне нужно» / «У меня есть» участников группы публикуются в группе, как раньше.
- **Поиск** по словам (основа слова — первые пять букв, ловит падежи): открытые записи без имён и ID с кнопками «Познакомиться N». Совпадение со скрытой записью — хозяину приходит «Кто-то ищет … Показать ему вас?».
- **Знакомство — только по согласию обоих** (`trh_links`): просьба со строкой о себе → «Соединить» / «Отказать»; для скрытых записей — «Показать» хозяином, затем «Познакомиться» ищущим. При согласии каждому приходит имя другого со ссылкой на профиль по ID (работает без @username). Разговоров коммутатор не хранит.
- **«Кто здесь»** — сводка без имён: число людей, записи по видам, частые темы и города; только группы от 3 человек и только открытые записи.
- **Отзывы и доверие** (`trh_reviews`): через неделю после знакомства бот спрашивает обоих «Полезно / Нейтрально / Нарушил Кодекс» (пункт и пара слов, `/skip`). Уровни: новичок; доверенный (участник группы или «Полезно» от нескольких людей без свежих нарушений; отметка в просьбе); под вопросом — при жалобах весом от 1,5 (участник группы — 1, остальные — 0,5) скрыт из поиска автоматически, человеку сообщается, оператору — кнопки «Отключить от сети» / «Оставить»; отключён — только решением оператора. «О себе» показывает отзывы без имён авторов. «Оставить» обнуляет учёт старых жалоб.
- **Лимиты в день:** 30 поисков; просьб о знакомстве 5 у новичка и 20 у доверенного; хозяину скрытой записи — не больше 5 предложений.
- Дальше по протоколу: удалённый MCP для подключения из своего ИИ, упаковка для самостоятельной установки.

## Коммутатор, шаг 2: API для программ и ИИ (private/src/Api.php, site/api.php)

- **Ключ.** `/key` в боте (или «О себе» → «Ключи для программ и ИИ»): список ключей (последние 4 знака, даты), «Создать ключ», «Отключить все ключи». Ключ показывается один раз; хранится только отпечаток SHA-256 (`trh_keys`). До 5 ключей у человека; ключ, которым не пользовались 90 дней, гаснет. Создать или отключить ключ через API нельзя — только в боте.
- **Запрос.** `POST https://dao.h1n.ru/api.php`, JSON `{"action": "...", "text": "..."}`, заголовок `Authorization: Bearer КЛЮЧ` (или поле `"key"` в JSON — на случай, если хостинг срезает заголовок). `GET` — справка со списком действий.
- **Действия = кнопки бота:** `menu`, `find` + text, `new:need|have|do|interest` + text, `who`, `list`, `mine`, `me`, `about` + text, `req:ID`, `ok:ID`, `no:ID`, `show:ID`, `del:ID`, `vis:ID`, `ren:ID`, `city:ID` + text, `renew`, `notify`, `rv:ID:u|n|x`, `pt:ID:1|2|3`.
- **Ответ** — то, что бот сказал бы этому человеку: `messages[].text`, следующие возможные действия `messages[].actions` и, после согласия обоих, `messages[].contacts` (имя и `tg://user?id=…`). Сообщения другим людям (просьбы, совпадения) по-прежнему идут через бот. Правила, лимиты и уровни доверия — те же, что в боте; сверху — не больше 600 запросов в день на человека.
